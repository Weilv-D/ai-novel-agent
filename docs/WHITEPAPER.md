# 【重构版】超长篇小说 AI 写作操作系统（AI Novel OS）完整架构白皮书

## 核心定位
这不是一个“AI 写作输入框”，而是一套面向长篇连载与 IP 孵化的“长篇小说操作系统”。

---

## 一、产品愿景与本质定义

### 1. 行业痛点与传统 AI 的局限
当前市面上的 AI 写作工具（如 ChatGPT、各类网文生成器）本质上更像“线性续写机器”，在面对百万字级超长篇小说时通常会暴露三类核心问题：

- **记忆崩塌**：超过上下文窗口后，设定遗忘、人物崩坏、伏笔断裂。
- **黑盒不可控**：作者无法干预 AI 的思考过程，只能反复 Roll（重生成）。
- **同质化与注水**：缺乏整体结构视野，导致行文拖沓、AI 味浓重。

### 2. 产品本质定义：Asset-Driven AI OS
本系统是一套由 Agent 驱动、基于资产演化的写作操作系统。其核心能力在于：

让作者围绕“作品工程”进行结构化协作，让 AI 在数月乃至数年的创作周期中，精准维护世界观、人物弧光、时间线、伏笔网络和作者专属文风。

---

## 二、核心产品哲学与底层逻辑

### 1. 六级分层渲染模型（Layered Rendering Model）
超长篇创作必须禁止“端到端直接生成”，改为“分层降维生成”。正文生成只在最底层发生，但受控于上层所有规则。

- **L1 作品层（Project）**：题材、受众、核心卖点、总体基调。
- **L2 世界层（World）**：地理、势力、力量体系、编年史、物理规则。
- **L3 角色层（Character）**：人物卡、关系网图谱、核心欲望、人物弧光。
- **L4 结构层（Story）**：主线/支线大纲、卷纲、三幕结构、高潮节点。
- **L5 章节层（Chapter）**：章节目标、核心冲突、信息揭示、悬念设计。
- **L6 场景层（Scene）**：POV（视点）、环境、行动、对白、潜台词、直接结果。

### 2. 万物皆可演化的“资产中心”（Asset-Centric）
小说中的每一块内容都不再是静态死文本，而是可演化数字资产：

- 大纲可调
- 人设可改
- 设定可热更新
- 正文可 patch 化修订

系统通过版本控制（类似写作版 Git）管理每一次资产变更。

### 3. “蝴蝶效应”引擎（Butterfly Effect Engine）
这是本系统的重要护城河。对任一对象的修改，都将触发自动拓扑影响分析。

例如：作者在 L2 世界层将“帝国兵权”从“皇帝”改给“四大公爵”。

系统动作：
- 自动扫描全书相关资产
- 高亮所有受影响角色关系
- 标出第四卷相关战争冲突
- 标记前文已埋但未提交修复的伏笔
- 生成可审阅的修复补丁（Patch）

## 三、Agent 矩阵编排体系（Multi-Agent Orchestration）

采用“总控路由 + 领域专家组”的架构。底层建议基于 LangGraph 或 AutoGen 类框架编排，或自研轻量 Agent Orchestrator。

### 1. 总控与路由 Agent（Writing Orchestrator）
**职责**：理解作者自然语言意图、拆解任务、分发给下游专家 Agent、汇总结果并进行风险拦截。

**典型交互**：
“帮我把前三章的节奏加快，主要突出男主的冷酷感。”

### 2. 领域专家 Agent（Domain Experts）

#### Lore Agent（世界观构架师）
负责设定条目的创建、补全与冲突检测，确保魔法体系或科幻设定形成逻辑闭环。

#### Character Agent（卡司导演）
追踪角色心理状态机、维持语言风格（Tone of Voice）、检测 OOC（Out of Character，人设崩坏）。

#### Outline Agent（剧情架构师）
监控小说节奏曲线与爽点密度，负责卷纲、章纲的拆解与重组。

### 3. 执行与质检 Agent（Execution & QA）

#### Draft Agent（主笔撰稿人）
基于 L6 场景卡，严格遵循 POV 和文风约束输出正文；负责扩写、缩写、风格转换。

#### Continuity Agent（逻辑审校编辑）
检测时间线错乱、常识认知越界（角色知道了不该知道的信息）、伏笔遗落。

#### Devil's Advocate Agent（毒舌主编）
反注水、反俗套，专门挑刺，提出剧情平淡的修改建议，逼迫系统生成更有张力的情节。

---

## 四、核心工作流与三态修改机制

放弃直接覆盖文本的粗暴方式，采用工程化的三态修改机制（Three-State Modification）：

### 1. Suggestion（建议态）
AI 在侧边栏提出优化建议或剧情走向，不触碰原始数据。

### 2. Patch（补丁态）
AI 生成结构化修改补丁（Diff / Patch 格式），在界面上左右分栏高亮显示新增/删除内容，等待作者审查。

### 3. Commit（提交态）
作者确认（Accept）后，修改正式生效。后台异步触发“蝴蝶效应引擎”，更新向量库、关系图谱和长期记忆摘要。

## 五、全局动态记忆系统（Dynamic Memory System，基于 GraphRAG）

这是支撑百万字级项目不崩盘的底层基石，建议采用“向量检索 + 知识图谱（GraphRAG）”混合架构。

### 1. 记忆分级结构

#### 工作记忆（Working Memory）
当前写作场景的局部上下文，例如最近 3 章文本与当前 Scene Brief。

#### 情节记忆（Episodic Memory）
已发生关键事件的摘要序列，自动从文稿中压缩抽取。

#### 语义记忆（Semantic Memory）
权威事实库，包括世界规则、角色状态机卡片、核心设定事实。

### 2. GraphRAG 检索策略
当生成新章节时，系统不是盲目检索相似文本，而是：

1. 提取当前场景中的关键实体（人物 A、物品 B、地点 C）
2. 通过图数据库（Neo4j / Nebula 等）查出 A 和 B 的关系变更历史，以及 C 的设定禁忌
3. 结合时间线筛选相关事件与依赖规则
4. 将精准的上下文打包成 Context Pack 喂给生成模型

## 六、商业与数据架构设计

### 1. 技术栈选型建议

#### 前端应用
- Next.js
- 协作富文本编辑器：TipTap / Lexical
- 画布可视化：React Flow / X6（关系图、时间线、结构图）

#### 后端服务
- NestJS 或 Python FastAPI

#### 记忆与数据库
- PostgreSQL：核心业务数据
- Qdrant / Milvus：向量检索
- Neo4j：知识图谱

#### 模型网关（One-API 风格架构）
- 推理与规划：DeepSeek-R1 / GPT-4o / Claude 3.5 Sonnet
- 正文生成：Kimi / 豆包 / Claude 3 Opus（偏文学性）
- 基建处理（摘要/提取）：GLM-4-Flash / GPT-4o-mini（低成本高并发）

### 2. 数据安全与 IP 保护（极重要）

#### 本地化 / 私有化策略
对于头部网文作者、工作室或影视团队，支持本地部署大模型（例如通过 vLLM 部署兼容模型），确保核心 IP 数据不出内网。

#### 记忆沙盒
每个作品的 RAG 库和知识图谱物理隔离，避免串库与数据污染。

### 3. 商业变现模式

#### B2C 创作者订阅模式（SaaS）
- **基础版**：限制月度生成字数，提供基础写作面板
- **Pro 版**：解锁多 Agent 对话、蝴蝶效应引擎、无限记忆检索、一键导出全套设定集

#### B2B 团队协同模式（PaaS）
面向工作室、影视剧本团队、剧本杀研发团队，提供：
- 多人协同
- 角色权限划分（大纲策划 / 填词枪手 / 主编）
- IP 资产数字化入库服务

## 七、产品演进路线（Roadmap）

### 阶段一：MVP（最小可行性产品）——“超级辅助者”
**核心目标**：打通分层创作闭环。

**关键特性**：
- 三栏工作台（左侧资产树 / 中侧编辑区 / 右侧 Agent 对话）
- 卷/章/场景规划生成
- 基础 RAG 记忆检索与上下文组装
- 统一接入 OpenAI / DeepSeek 兼容接口

### 阶段二：专业化构建——“虚拟协作团队”
**核心目标**：实现状态追踪与长篇强控。

**关键特性**：
- 上线“蝴蝶效应引擎”（影响范围拓扑图）
- 引入 GraphRAG 增强逻辑推理
- 实装 Continuity Agent（防崩坏、防吃书审校系统）
- 引入三态修改（Patch 补丁机制）

### 阶段三：IP 生态与自适应进化——“小说操作系统”
**核心目标**：构建产品壁垒，实现内容资产增值。

**关键特性**：
- 文风克隆引擎：学习作者独有语感，摆脱“AI 味”
- 跨媒介资产转换：将小说世界观和剧情转换为漫画分镜脚本、游戏策划案等结构化输出
- 读者留存分析与“网文黄金三章”诊断看板

---

## 结语

这个产品的终极壁垒，并不在于接入了多么强大的大模型，而在于：

- 对创作工程的结构化抽象能力
- 对长程状态机的维护能力

它不是在替代人类写作，而是在为作家提供一套抵御长篇连载熵增的“外骨骼机甲”。
