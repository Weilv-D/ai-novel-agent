# AI 超长篇小说写作 Agent - MVP 范围定义

## 文档信息
- 项目名称：AI 超长篇小说写作 Agent 应用
- 文档类型：MVP 范围定义（MVP_SCOPE）
- 版本：v1.0
- 状态：初版
- 创建日期：2026-03-12

---

## 1. MVP 目标

**核心目标**：验证"对象级 Agent 写作系统"的核心价值，即：
1. AI 能否理解作品工程而不仅是生成文本
2. 修改传播机制是否有效
3. 三态修改机制是否给用户足够的控制感

**成功标准**：
- 用户能创建一个完整的小说项目（人物+设定+大纲+章节）
- 用户能通过对话让 AI 修改任意对象
- 修改后系统能识别影响范围
- 用户能预览、确认或回滚 AI 的修改

## 2. 必做功能（Must Have）

### 2.1 项目管理
- [ ] 创建/编辑/删除项目
- [ ] 设置作品基本信息（题材、受众、目标字数）
- [ ] 项目状态标记（构思/连载/完结）
- [ ] 项目快照与回滚（手动触发）

### 2.2 世界观与设定库
- [ ] 创建/编辑/删除设定条目
- [ ] 设定分类（魔法体系、地理、历史、规则等）
- [ ] 设定与章节/人物的关联显示
- [ ] AI 对话式修改世界观
- [ ] 修改后影响范围识别

### 2.3 人物系统
- [ ] 创建/编辑/删除人物
- [ ] 人物档案（姓名、外貌、性格、背景等）
- [ ] 人物关系网络（简单列表展示）
- [ ] AI 对话式调整人设
- [ ] 修改后影响章节识别

### 2.4 故事结构
- [ ] 创建/编辑/删除卷
- [ ] 创建/编辑/删除章节
- [ ] 章节大纲编辑
- [ ] 章节排序
- [ ] AI 生成章纲（基于项目设定）

### 2.5 场景与正文
- [ ] 创建/编辑/删除场景
- [ ] 富文本编辑器（基于 TipTap）
- [ ] 场景参数设置（POV 人物、地点）
- [ ] AI 场景生成（基于大纲）
- [ ] AI 局部改写（选中文本）

### 2.6 对象级 AI 对话
- [ ] 右侧固定对话面板
- [ ] 基于当前对象上下文对话
- [ ] 支持"建议"和"执行"两种模式
- [ ] 对话历史记录

### 2.7 三态修改机制
- [ ] Suggestion（建议）：AI 生成初始建议
- [ ] Patch（补丁）：用户确认后转为预览状态
- [ ] Commit（提交）：应用到目标对象
- [ ] Discard（丢弃）：用户拒绝
- [ ] 建议列表管理

### 2.8 影响分析
- [ ] 简单引用追踪（谁引用了谁）
- [ ] 修改后列出受影响对象
- [ ] 风险等级标记（高/中/低）

### 2.9 记忆与检索
- [ ] 章节摘要自动生成（基础版）
- [ ] 关键事实抽取（基础版）
- [ ] 简单语义检索（基于 pgvector）

### 2.10 连续性检查
- [ ] 设定冲突检查（基础规则匹配）
- [ ] 人设一致性检查（关键词检测）
- [ ] 问题报告输出

### 2.11 导出功能
- [ ] 导出 TXT
- [ ] 导出 Markdown

### 2.12 认证与安全
- [ ] 用户注册/登录
- [ ] API Key 认证
- [ ] 基础速率限制

## 4. 技术依赖

### 4.1 外部依赖
- **LLM API**：支持 OpenAI 兼容接口（可自部署模型）
- **PostgreSQL**：16+ 版本，需 pgvector 扩展
- **Redis**：用于缓存和任务队列
- **Node.js**：18+ 版本

### 4.2 技术栈确认
| 组件 | 技术 | 版本要求 |
|------|------|---------|
| 前端 | Next.js | 14+ |
| 后端 | FastAPI | 0.104+ |
| 编辑器 | TipTap | 2.1+ |
| 数据库 | PostgreSQL | 16+ with pgvector |
| 缓存 | Redis | 7+ |
| 任务队列 | Celery | 5.3+ |

## 5. 验收标准

### 5.1 功能验收
1. **项目创建流程**：用户能在 5 分钟内创建一个完整项目（含基础设定和人物）
2. **AI 对话修改**：用户能通过对话成功修改至少 3 种不同类型对象
3. **影响分析**：修改对象后，系统至少识别出一个受影响对象
4. **三态机制**：用户能完成建议→补丁→提交的完整流程
5. **导出**：项目能成功导出为 TXT 和 Markdown

### 5.2 性能验收
- API 响应时间 < 500ms (P95, 非生成操作)
- LLM 首次响应 < 5s
- 单个项目支持 > 100 个章节
- 单个项目支持 > 50 个人物

### 5.3 质量验收
- 所有 API 端点有单元测试覆盖率 > 60%
- 关键业务逻辑有集成测试
- 无已知严重 Bug
- 通过基本安全检查（SQL 注入、XSS 等）

## 7. 技术债清单

### 7.1 已知简化
1. **认证系统**：MVP 仅实现简单 API Key，无复杂权限
2. **向量存储**：使用 pgvector 而非专用向量数据库
3. **影响分析**：仅实现简单的引用追踪，无复杂依赖图算法
4. **记忆系统**：仅实现基础摘要和检索，无分层记忆架构
5. **实时性**：无 WebSocket 推送，使用轮询

### 7.2 未来需改进
1. 迁移至专用向量数据库（Qdrant）
2. 实现复杂影响分析算法
3. 增加实时推送机制
4. 优化 Prompt 模板管理
5. 增加更细粒度的权限控制

## 8. MVP 里程碑

### 里程碑 1：基础框架（2 周）
- 前后端项目初始化
- 数据库模型定义与迁移
- 基础 API 框架搭建
- 前端路由与布局

### 里程碑 2：核心对象 CRUD（2 周）
- 项目、人物、世界观、章节、场景 CRUD
- 前端表单与列表页面
- 基础关联关系实现

### 里程碑 3：编辑器与对话（2 周）
- TipTap 编辑器集成
- Agent 对话面板
- LLM 调用封装

### 里程碑 4：三态修改机制（2 周）
- Suggestion/Patch/Commit 实现
- 影响分析基础版
- 前端预览与确认流程

### 里程碑 5：记忆与连续性（1 周）
- 基础记忆抽取与检索
- 简单连续性检查

### 里程碑 6：导出与收尾（1 周）
- 导出功能
- 测试与 Bug 修复
- 文档完善

**总计**：约 12 周（与实施计划一致）

## 9. 风险与缓解

### 9.1 技术风险
| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| LLM API 不稳定 | 高 | 实现重试机制，支持多模型切换 |
| pgvector 性能不足 | 中 | 监控性能，预留迁移接口 |
| 前端状态复杂 | 中 | 使用 Zustand 简化状态管理 |

### 9.2 产品风险
| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| 用户不理解三态机制 | 中 | 增加引导提示和帮助文档 |
| AI 生成质量不佳 | 高 | 优化 Prompt，支持模型切换 |
| 功能过于复杂 | 中 | MVP 聚焦核心流程，避免过度设计 |
