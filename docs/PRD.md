# AI 超长篇小说写作 Agent 应用 PRD

## 1. 文档信息
- 项目名称：AI 超长篇小说写作 Agent 应用
- 文档类型：产品需求文档（PRD）
- 版本：v1.0
- 状态：初版
- 目标：定义一款面向超长篇小说创作、支持对象级 AI 交互与 Agent 式修改执行的产品。

---

## 2. 项目背景

现有 AI 写作工具多数聚焦于：
- 续写一段文字
- 润色一章内容
- 临时生成设定和人物简介

但对于真正的长篇、超长篇小说创作，尤其是网文、系列小说、可改编 IP 项目，真正的难点不是“写出一段像样的文字”，而是：
- 在长周期内保持世界观一致
- 维持人物弧光与关系逻辑
- 管理主线、支线、卷纲、章纲和节奏
- 处理中途大量修改后的连锁影响
- 让作者始终掌控创作，而不是被 AI 带偏

因此，需要一款不是“聊天写作工具”，而是“围绕作品工程长期运转的 Agent 写作系统”。

---

## 3. 产品定位

### 3.1 产品定义
本产品是一款面向超长篇小说创作的 AI Agent 写作平台。它支持用户围绕作品中的核心对象（文稿、世界观、设定、人物、剧情结构等）进行持续对话、修改、重构，并由系统完成影响分析、一致性维护与上下文同步。

### 3.2 一句话定位
一个可与文稿、人物、设定、世界观和结构直接对话，并由 AI Agent 执行修改与维护的超长篇小说创作系统。

### 3.3 核心价值
- 从“生成文本”升级为“管理作品工程”
- 从“单轮对话”升级为“对象级 Agent 协作”
- 从“临时帮助”升级为“长期写作系统”

---

## 4. 目标用户

### 4.1 核心用户画像

#### A. 网文作者
- 有持续日更或周更需求
- 追求长线剧情稳定推进
- 对人物、人设、爽点、节奏高度敏感
- 经常需要在写作中途调整剧情方向

#### B. 职业作者 / 编剧团队
- 重视结构规划和项目管理
- 需要系统化管理人物、设定、时间线
- 需要版本控制、多人协作和精修能力

#### C. IP 孵化团队
- 需要从小说阶段就管理可改编资产
- 重视世界观、人物关系网和主线结构
- 需要后续服务剧本化、漫画化等扩展能力

#### D. 高强度创作爱好者
- 希望 AI 既能辅助思考，也能参与改稿
- 不满足于纯聊天式写作
- 需要一个像 IDE 一样的创作平台

### 4.2 用户痛点
- 写到中后期世界观开始混乱
- 人物人设不稳定，越写越偏
- 大纲、正文、设定互相脱节
- 改了设定后，不知道旧文稿哪里要改
- AI 文笔可以，但结构控制差
- AI 能陪聊，但不像真正的编辑和写作系统

## 5. 产品目标

### 5.1 业务目标
- 提供面向长篇与超长篇小说的专业创作工具
- 建立比普通 AI 写作助手更高的用户粘性与专业壁垒
- 形成可拓展的 Agent 创作平台能力

### 5.2 用户目标
- 提高创作效率
- 提高长篇一致性
- 降低改稿成本
- 增强对作品结构与资产的掌控力

### 5.3 产品成功标准
- 用户能够持续管理一部长篇小说项目
- 修改任意对象后，系统能识别影响并辅助修复
- 用户感觉 AI 在“理解作品工程”，而不只是生成段落

## 6. 设计原则

### 6.1 分层创作
采用作品层、世界层、角色层、故事层、章节层、场景层的分层控制架构。

### 6.2 对象优先
把人物、设定、世界观、章节、场景、伏笔都视为一等对象，而不是普通文本片段。

### 6.3 修改可传播
任何修改都应具备影响分析能力。

### 6.4 AI 可控
AI 生成与修改必须可预览、可确认、可回滚。

### 6.5 作者主导
AI 是协作系统，不替代作者，不越权主导创作。

## 8. 核心功能模块

## 8.1 项目管理模块

### 功能说明
用于创建、查看、配置和管理作品项目。

### 功能点
- 创建项目
- 设置题材、主题、目标读者、风格、字数目标
- 查看项目概览
- 作品阶段标记（构思 / 搭建 / 连载 / 精修 / 完结）
- 快照与归档

### 关键价值
为整个作品工程提供容器。

---

## 8.2 世界观与设定库模块

### 功能说明
统一管理世界观、规则、地点、势力、历史、道具、能力体系等。

### 功能点
- 创建设定条目
- 编辑 canonical facts
- 管理设定的引用关系
- 显示相关章节与人物
- AI 对话式修改世界观
- 修改后输出影响分析

### 示例交互
- “把这个修炼体系改得更残酷一点”
- “如果这里加入记忆代价，会影响哪些剧情？”

### 关键价值
保证世界观结构化、可检索、可持续修改。

---

## 8.3 人物系统模块

### 功能说明
管理角色档案、关系网络、弧光进展、语言风格和动态状态。

### 功能点
- 人物卡创建与编辑
- 核心欲望/缺陷/秘密设置
- 当前状态与弧光阶段跟踪
- 角色关系图
- AI 对话式人设调整
- 受影响章节识别
- 台词风格建议与修订

### 示例交互
- “让她更危险，但仍保持优雅”
- “他对主角的信任转折太快了，重做关系推进”

### 关键价值
减少人设崩坏，提升人物成长线稳定性。

---

## 8.4 故事结构与大纲模块

### 功能说明
管理主线、支线、卷纲、章纲、场景节点和节奏设计。

### 功能点
- 作品总纲编辑
- 卷/章/场景树管理
- 支线与主线关联
- 拖拽调整顺序
- AI 生成章纲/场景卡
- 节奏问题诊断
- 伏笔账本联动

### 示例交互
- “把第二卷高潮提前三章”

### 关键价值
从结构层控制小说，而非只在正文层修修补补。

## 8.5 文稿编辑与局部改写模块

### 功能说明
在章节和场景级进行正文创作、续写、重写、润色与风格调整。

### 功能点
- 富文本 / Markdown 编辑
- 场景级正文生成
- 局部段落改写
- 扩写 / 缩写 / 重写 / 改 POV
- 风格迁移
- 与当前对象上下文联动

### 示例交互
- “保留剧情功能，把这段写得更克制”

### 关键价值
让 AI 在不破坏结构与设定的前提下深度参与写作。

## 8.6 对象级 AI 对话模块

### 功能说明
针对当前对象提供 Agent 式对话能力。对象包括：项目、人物、设定、章节、场景、主线、支线等。

### 功能点

### 咨询态示例

### 执行态示例

### 关键价值

## 9. 关键交互设计

### 9.1 页面框架
建议采用三栏式：
- 左栏：对象树与导航
- 中栏：主内容编辑区
- 右栏：当前对象的 AI Agent 对话区

### 9.2 AI 执行前选择作用范围
- 仅建议
- 仅改当前对象
- 同步改相关对象
- 批量修复相关章节

### 9.3 Patch 预览机制
AI 不直接覆盖内容，而是先展示：
- 修改前/后 diff
- 涉及字段
- 受影响对象
- 风险提示

### 9.4 修改后自动动作
- 更新摘要
- 更新记忆
- 更新状态
- 生成影响报告
- 触发一致性检查

### 10.1 新建项目流程
1. 用户创建项目
2. 设置作品参数
3. AI 协助生成初始 Story Bible
4. 自动生成世界观和人物草稿

1. 选择卷 / 章
2. 生成章纲与场景卡
3. 逐场景生成正文
4. 局部对话修改
5. 审校并确认
6. 自动生成摘要和更新记忆

### 10.3 设定修改流程
1. 打开设定条目
2. 与 AI 对话修改
3. 生成 patch
4. 查看影响分析
5. 确认应用
6. 批量检查受影响文稿

### 10.4 人物调整流程
1. 打开人物对象
2. 输入修改目标
3. AI 给出人设补丁和关系影响
4. 用户确认
5. 系统标记受影响章节并给出修复建议

## 15. 风险与对策

### 风险 1：AI 写得像样，但不推进剧情
对策：场景生成强制绑定目标、冲突、结果结构。

### 风险 2：设定和人物越写越乱
对策：canonical facts + 连续性检查 + 修改影响分析。

### 风险 3：作者担心 AI 乱改
对策：patch 预览、版本快照、可回滚、范围控制。

### 风险 4：系统太复杂，门槛高
对策：MVP 聚焦核心对象与核心流程，避免一次做太多。

## 16. 最终结论

本产品的真正创新点，不是“让 AI 帮你写小说”，而是：

1. 让作品中的每个核心对象都能与 AI 对话
2. 让 AI 以 Agent 方式对对象执行修改和维护
3. 让修改可传播、可追踪、可修复
4. 让作者在长篇创作中长期保持掌控

最终，它应当成为：
**超长篇小说创作的对象级 Agent 操作系统。**

## 17. 产品战略补充（重构版收敛）

### 17.1 核心产品哲学
本产品不是“线性续写机器”，而是由 Agent 驱动、基于资产演化的长篇小说操作系统。

它要解决的不是单次生成质量，而是超长周期中的：
- 记忆稳定
- 结构控制
- 修改传播
- 资产一致性
- 作者主导权

### 17.2 六级分层渲染模型
为了避免端到端直接生成导致的失控，系统采用六级分层：
- L1 作品层：题材、受众、卖点、总体基调
- L2 世界层：地理、势力、力量体系、历史、物理规则
- L3 角色层：人物卡、关系图谱、核心欲望、人物弧光
- L4 结构层：主线/支线、卷纲、三幕结构、高潮节点
- L5 章节层：章节目标、冲突、信息揭示、悬念设计
- L6 场景层：POV、环境、行动、对白、潜台词、直接结果

正文生成仅在 L6 发生，但严格受上层约束。

### 17.3 资产中心与版本控制
小说中的每个对象都应被视为可演化资产，而不是静态文本：
- 大纲可调
- 人设可改
- 设定可热更新
- 文稿可 patch 化修订

系统应通过版本快照与对象级版本控制，对每次变化进行追踪。

### 17.4 蝴蝶效应引擎
对任一对象的修改，应触发自动拓扑影响分析。例如修改一条世界规则，系统应自动识别：
- 哪些人物和关系受影响
- 哪些章节和卷冲突将出现
- 哪些伏笔链条可能断裂
- 哪些历史文本需要修复

该机制是系统从“AI 编辑器”升级为“小说操作系统”的关键。

### 17.5 Agent 矩阵的强化理解
在已有 Agent 体系基础上，强调以下角色价值：
- Writing Orchestrator：任务理解、路由与风险拦截
- Lore Agent：世界观闭环维护
- Character Agent：心理状态机与 OOC 检测
- Outline Agent：节奏曲线与结构拆解
- Draft Agent：正文撰写与风格转换
- Continuity Agent：时间线、认知边界、伏笔检查
- Devil's Advocate Agent：反注水、反平庸、强化戏剧张力

### 17.6 三态修改机制的产品意义
除了 Suggestion / Patch / Commit 的工程意义，还应强调产品体验意义：
- Suggestion：帮助作者保留思考主导权
- Patch：帮助作者在结构化 diff 中审稿
- Commit：帮助系统在确认后同步更新记忆、索引和图谱

### 17.7 Dynamic Memory System 与 GraphRAG 方向
在 MVP 可先用“PostgreSQL + 向量检索 + 结构化记忆抽取”实现基础版。
在 V2/V3 再逐步升级为 GraphRAG：
- Working Memory：最近章节与当前 Scene Brief
- Episodic Memory：关键事件摘要序列
- Semantic Memory：世界规则、人物状态、设定权威事实

检索不应只靠文本相似度，还应结合实体、时间线、关系链与剧情状态。

### 17.8 商业化方向补充
产品商业模式可以分为：
- B2C SaaS：面向个人作者的订阅制
- B2B/PaaS：面向工作室、影视、剧本团队的协作平台

其中高阶卖点包括：
- 无限记忆检索
- 蝴蝶效应引擎
- 多 Agent 协作
- 本地化 / 私有化部署
- IP 资产数字化管理

### 17.9 Roadmap 再确认
#### 阶段一：MVP（超级辅助者）
- 三栏工作台

- 基础 RAG 检索

#### 阶段二：专业化构建（虚拟协作团队）

#### 阶段三：IP 生态与自适应进化（小说操作系统）
- 文风克隆
- 跨媒介资产转换
- 留存分析与黄金三章诊断

### 17.10 最终判断
这个产品真正的护城河，不在于“调用了哪个最强模型”，而在于：
- 对创作工程的结构化抽象能力
- 对长程状态机的维护能力
- 对修改传播与一致性修复的系统能力

它的价值，不是替代作者，而是为作者提供一套抵御长篇创作熵增的外骨骼系统。
